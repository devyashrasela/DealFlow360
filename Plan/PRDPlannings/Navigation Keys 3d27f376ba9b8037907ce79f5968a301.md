# Navigation Keys

# 1. Purpose

This specification defines the global routing and persistent navigation layout for the entire DealFlow360 platform. It establishes the primary UI paradigm used across all internal modules—specifically, the standard "List-to-Detail" transition—and maps every top-level tab to its exact screen destination.

### 2. The Core Navigation Paradigm

The internal workspace utilizes a persistent horizontal top navigation menu across all screens. To maintain cognitive consistency for the user, the platform strictly adheres to the following structural rules:

- **Active State Indicator:** The currently active module is indicated by a white highlighted tab in the top navigation bar.
- **The List-to-Detail Pattern:** Every major data entity (Quotations, Approvals, Fulfillment, Subscriptions, Invoices) is structured as exactly two screens.
    1. **The List Screen:** The default landing page for the tab, displaying all records in a table/grid format.
    2. **The Detail Screen:** A deep-dive workspace for a single record, opened exclusively by clicking a specific row on the List Screen.

### 3. Screen Routing Map

#### 3.1 Internal User Navigation (Sales Workspace)

The following tabs are visible to authenticated internal users (Sales Reps, Managers, Finance, Ops).

   | N/A | Central hub; provides quick summary cards and links out to every module below.   |

#### 3.2 Global Utility Actions (Internal)

Available persistently above or alongside the main tabs:

- **Reload Data:** Refreshes pricing, stock, and approval states directly from the backend without a hard browser reload.
- **Go to Back-end:** Opens the backend configuration area (Products, Price Lists, Discount Tiers, Warehouses).
- **Close Workspace:** Ends the current working session.

#### 3.3 External Customer Navigation

Customers access a completely isolated UI architecture and do not see the internal tabs.

- **My Quotation / Messages / Profile** $\rightarrow$ Opens **Screen 11** (Customer Portal).

### 4. Functional Requirements

| **ID** | **Requirement Description** | **Priority** |
| --- | --- | --- |
| **FR-NAV-01** | **Persistent Top Menu:** The top navigation bar must remain pinned and visible across all internal workspace screens (Screens 2 through 15) to allow instant module switching.   | **Must** |
| **FR-NAV-02** | **Active Tab Highlighting:** The system must automatically apply the white highlighted state to the tab corresponding to the user's current module location.   | **Must** |
| **FR-NAV-03** | **List-to-Detail Click Routing:** Clicking anywhere on a data row within a List Screen (Screens 3, 5, 7, 9, 12) must route the user to the corresponding Detail Screen (Screens 4, 6, 8, 10, 13) pre-loaded with that record's data.   | **Must** |
| **FR-NAV-04** | **Breadcrumb/Back Navigation:** Detail Screens must provide a clear mechanism (e.g., a "Back to List" button or clicking the top nav tab again) to return to the parent List Screen.   | **Must** |
| **FR-NAV-05** | **Role-Based Tab Visibility:** The navigation bar must dynamically hide tabs based on user permissions (e.g., hiding configuration or advanced reporting from baseline Sales Reps if strictly enforced by the backend).   | **Should** |
| **FR-NAV-06** | **Customer Portal Isolation:** Customers logging into the system must immediately land on Screen 11 and must never be exposed to the internal tabbed navigation. | **Must** |

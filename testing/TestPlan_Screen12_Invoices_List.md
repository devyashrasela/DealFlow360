# Test Plan — Screen 12: Invoices (Unified Financial Ledger List)

**Product:** DealFlow360
**Source:** Customer Portal Negotiation & Invoices Ledger specs, both versions (Section 3.2, FR-INV-01 through FR-INV-06)

---

## 1. Test Scope

Covers the unified ledger aggregation (standard invoices, subscription cycles, proration deltas, credit notes), filter pills, source deep-linking, inline payment recording modal, and status badge accuracy. This screen is the reconciliation point for everything generated by Screens 4 (quotation confirm), 10 (subscription proration/cancellation), and 11 (customer confirmation) — so several tests here are really integration tests confirming those upstream screens actually feed this ledger correctly.

---

## 2. Preconditions / Test Data Setup

- At least one of each document type: standard one-time invoice, recurring subscription cycle invoice, proration delta invoice, and a credit note (from a cancellation).
- At least one invoice in each status: Posted, Paid, Partially Paid (if implemented), Credited, Overdue.
- A credit note with a negative balance ready to be applied against an open invoice.
- Aggregated counters pre-computed manually against seed data for cross-checking (Total Outstanding Receivables, Overdue Count, Total Credited).

## 9. Non-Functional Test Cases

| ID | Test | Expected Result |
|---|---|---|
| INV12-NFR1 | Reconciliation integrity | Sum of all Paid allocations + remaining Balance Due always equals Total Amount, with zero fractional-cent drift — test specifically with amounts likely to trigger rounding issues (e.g., tax-inclusive totals with 3+ decimal intermediate values) |
| INV12-NFR2 | Global Reload Data refresh | After an external change (e.g., a payment recorded elsewhere, or a new invoice generated), click Reload Data | Ledger re-fetches and reflects the change without requiring logout/login |
| INV12-NFR3 | Multi-tenant isolation | Log in under a different organization | Only that organization's invoices/credit notes are visible |

---

## 10. Priority Summary for Judges/Demo

**INV12-23 through INV12-25** are your best integration demo — showing that a single confirm/proration/cancellation action elsewhere in the app produces the correct financial document here, live, is a much stronger proof point than showing this screen in isolation with static seed data. **INV12-05** (aggregated counter accuracy) is worth a quick manual spot-check before the demo, since summary-card-vs-table mismatches are the easiest bug for judges to spot instantly.
